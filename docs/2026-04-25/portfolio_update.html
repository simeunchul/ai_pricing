왜 일괄 갱신이 필요했나

같은 날 오후 Buehler 2019 직접 구현 (커밋 e12dc14) 으로 Layer B4 의 판정이 "수렴 미완 (PARTIAL +7.8%)" 에서 "PASS (+24.5%)" 로 뒤집혔다. 이것은 단순히 한 줄 수치 변경이 아니라, 면접용 포트폴리오 전체의 narrative 가 바뀌는 사건이다:

  • 이력서의 "핵심 성과" 섹션 — 기존 5개 (B4 빠짐) → 6개 (B4 추가)
  • 블로그 4편 — 기존엔 "정직한 실패 보고" 였으나 이제 "5번 실패 → 1번 성공" 의 가장 강한 스토리
  • 풀스택 상태 리포트 — B4 칸이 빨간 "미완" 에서 초록 "PASS" 로
  • 비교 CSV — Buehler v2 행 추가하지 않으면 다른 보고서들과 수치 모순

접근

7. 용어 정리집 (Glossary)

용어한 줄 설명본문에서의 역할
CVaR (Conditional Value-at-Risk) "최악의 5% 손실의 평균" — 분포 꼬리 위험을 한 숫자로 압축한 지표 B4 의 단일 평가 지표. 모든 파일에서 핵심 수치는 CVaR ratio
BSM Δ (Black-Scholes-Merton Delta) 옵션 가격을 기초자산 변동에 1차 연동시키는 전통적 헤지 비율 모든 비교의 기준선 (baseline = 0%, ratio = 1.0)
TC (Transaction Cost) 거래비용. 30bps = 거래대금의 0.3% TC=0 sanity vs TC=0.3% real-world 두 환경 분리. 플랜 목표는 TC=0.3% 환경에서 ≥20%
PPO (Proximal Policy Optimization) 가장 널리 쓰이는 강화학습 알고리즘. E[reward 합] 을 최대화 5번 실패의 주체. CVaR (꼬리 위험 최소화) 와 목적함수가 직교라 본질적으로 부적합
PG-on-CVaR Policy Gradient 를 CVaR loss 에 직접 적용. gym/PPO 없이 loss.backward() 한 줄 Buehler 2019 의 핵심. 알고리즘 변경의 본질이자 +24.5% 의 원인
narrative 면접·블로그에서 통하는 "한 줄 스토리" "수렴 미완 → 정직한 실패" 에서 "5번 실패 → 1번 성공" 으로 전환된 것이 이번 갱신의 핵심
untracked git 이 아직 추적하지 않는 파일 (한번도 add 안된 신규 파일) CLAUDE.md 가 untracked 상태로 끊김 → 분리 커밋 사유
wincredman Windows Credential Manager — git 이 GitHub 인증 정보 저장하는 백엔드 비대화형 세션에서 prompt 띄우려다 실패 → push 사용자 위임 사유
plan target 9주 스프린트 플랜에 사전 명시된 정량 목표 (B4: CVaR 개선 ≥ 20%) +24.5% 가 PASS 인 이유. 이 숫자가 없으면 "그래서 얼마면 좋은 건데" 답이 없음
ratio (CVaR ratio) policy CVaR ÷ BSM CVaR. 1보다 작으면 BSM 보다 좋음 0.755 = (1 − 0.755) × 100 = 24.5% 개선 의 산식 출발점
