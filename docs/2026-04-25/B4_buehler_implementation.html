Layer B4 — Buehler 2019 직접 구현으로 플랜 목표 달성

2026-04-25 · PPO 5번 실패 후 알고리즘 변경. Direct policy gradient on CVaR loss. CPU 2분 16초 학습으로 +24.5% CVaR 개선 (플랜 ≥20% 목표 PASS).

한 줄 결과 — Buehler-Gonon-Teichmann-Wood (2019) 의 핵심 통찰 "PPO 안 쓰고 CVaR loss 에 직접 backward" 로 PPO 5번 시도 모두 못 한 것을 단 136초 (CPU) 만에 ratio 0.755 = +24.5% 개선 달성.

1. 무엇을 시도했는지

5번 시도 후 진단: "PPO 의 E[reward] 최적화 ≠ CVaR 최소화. 직교 함수. Hyperparameter 튜닝으로 해결 불가, 알고리즘 변경 필수." (자세한 진단: why_dh_failed.html)

이번 시도 — Buehler 2019 원논문 직접 구현

논문의 핵심 통찰: 

Loss = CVaR_α [ payoff − Σ_t π_θ(s_t) · ΔS_t + Σ_t TC · |Δπ_θ| ]

PPO 와 다른 점 3가지:

  1. gym env 사용 안 함. PyTorch tensor 로 batch GBM 직접 시뮬레이션 — gradient 가 policy 까지 흐를 수 있게.
  2. reward shaping 없음. dense per-step reward 가 BSM attractor 를 만들었던 게 5번 실패의 원인. terminal CVaR loss 만 사용.
  3. policy gradient 가 batch 단위. CVaR 는 batch quantile 로만 정의되므로 advantage estimation 이 아니라 batch 전체 loss 로 backward.

2. 무엇이 실패했고 왜

PPO 5번 실패의 핵심 메커니즘 (자세한 진단은 why_dh_failed.html):

실패 원인구체적 설명
① 목적함수 mismatch PPO 는 max E[Σ γt·rewardₜ]. 우리가 원한 건 min CVaR5%[terminal_loss]. 두 함수 직교 — PPO 는 평균 reward 잘 받지만 worst-case 신경 안 씀.
② Dense shaping BSM attractor Per-step reward −λ(V_hedge_change − V_opt_change)² 의 minimum 위치가 정확히 BSM Δ. 학습 길어지면 BSM 으로 수렴, 그 너머 탐색 불가.
③ Entropy collapse 학습 후반 PPO std 가 1.0 → 0.025 까지 collapse. deterministic policy 가 새 path 적응 못 함.

Hyperparameter 튜닝 (loss multiplier, learning rate, entropy bonus, training step, reward shaping 강도, action space 크기) 모두 시도. 어떤 조합으로도 위 3가지 메커니즘 못 깨뜨림. → "알고리즘 자체 변경 필요" 결론.

3. 어떻게 해결했는지

3.1 핵심 코드 — Differentiable batch simulator

새 파일 packages/ai_hedging/src/ai_hedging/agents/buehler_pg.py: 

def simulate_batch(policy, cfg, batch_size, ...) -> torch.Tensor:
    """gradient flows from policy → action → S_path → terminal_pnl."""
    S    = torch.full((B,), S0)
    cash = torch.full((B,), bsm_premium)
    hedge = torch.zeros(B)

    for t in range(n_steps):
        obs = build_obs(S, t, hedge, cash, premium)
        new_hedge = policy(obs)                  # ← differentiable
        cash -= tc * (new_hedge - hedge).abs() * S
        hedge = new_hedge

        Z = torch.randn(B)
        S_next = S * torch.exp(drift_dt + diff_dt * Z)
        cash = cash * exp_r_dt + hedge * (S_next - S)
        S = S_next

    payoff = torch.relu(S - K)
    cash = cash - tc * hedge.abs() * S          # close cost
    return cash - payoff                         # batch (B,)


def cvar_loss_fn(pnl, alpha=0.05):
    """Differentiable CVaR — sort + bottom α mean."""
    n_tail = max(int(alpha * pnl.numel()), 1)
    sorted_pnl, _ = torch.sort(pnl)
    return -sorted_pnl[:n_tail].mean()           # ← scalar, diff'able


# Training loop:
for ep in range(n_epochs):
    pnl = simulate_batch(policy, cfg, batch_size=4096~16384)
    loss = cvar_loss_fn(pnl, 0.05)
    loss.backward()                              # ← single line magic
    optimizer.step()

3.2 PPO 와의 핵심 차이

요소PPO (5번 실패)Buehler PG-CVaR (이번)
Environment gym.Env (non-differentiable) PyTorch tensor 직접
학습 신호 per-step reward + advantage terminal CVaR loss
Reward shaping dense (BSM attractor 형성) 없음
Policy update clip(ratio·A) — surrogate ∂CVaR/∂θ 직접
Exploration Gaussian noise + entropy bonus Sigmoid 출력 + GBM 자체 randomness
Hyperparameter 민감도 매우 높음 (ent_coef, lr, n_steps...) 낮음 (batch_size, lr, epochs)
