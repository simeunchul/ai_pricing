2.2 MSE 옵티마이저의 "주목" 메커니즘

MSE loss 는 오차의 제곱을 평균. 가격이 큰 샘플(ITM)에서 작은 상대오차도 MSE 에 큰 기여, 가격이 작은 샘플(OTM)은 오차 절대값이 작아서 MSE 가 사실상 무시.

2.3 두 증상의 공통 뿌리

증상표면적 설명진짜 원인
Underfit (val_mse 하강 지속) 데이터/epoch 부족 MSE 가 ITM 에 묶여 ATM/OTM 구조를 배울 여유 없음
Deep OTM 838% 상대오차 분모 작음 MSE 가 OTM 을 사실상 학습 안 시킴 → 절대오차 ≈ ATM 수준 → 분모로 나누니 폭발

3. 해결 1 — 학습 개선

3.1 Loss function 교체 (가장 효과 큼)

Loss수식구현 난이도예상 효과학술 근거
현재 MSE (pred − y)² — underfit Hutchinson 1994 (원 논문)
권장 ① Relative MSE ((pred − y) / (y + ε))² 1줄 수정 ATM rel_err 즉시 < 2% Ferguson-Green 2018
권장 ② Log-space MSE (log(pred+ε) − log(y+ε))² 1줄 수정 전 범위 균등 + 수치 안정적 Liu-Oosterlee-Bohte 2019
권장 ③ Vega-weighted MSE ((pred − y) / vega)² 중 (vega 사전계산) IV 오차에 직접 대응 Horvath 2021 부록 A

구현 — Relative MSE 패치 예시

대상: packages/ai_pricing/src/ai_pricing/nn_pricer/train.py:57, :70, :81 
# Before (train.py:57)
loss_fn = torch.nn.MSELoss()

# After — relative MSE 추가 + CLI 옵션
def make_loss(name: str):
    eps = 1e-4
    if name == "mse":
        return torch.nn.MSELoss()
    if name == "rel":
        return lambda pred, y: (((pred - y) / (y.abs() + eps)) ** 2).mean()
    if name == "log":
        return lambda pred, y: ((torch.log(pred.clamp_min(eps))
                                 - torch.log(y.clamp_min(eps))) ** 2).mean()
    raise ValueError(name)

loss_fn = make_loss(args.loss)  # --loss {mse,rel,log}

4. 해결 2 — 평가 재정비 (838% 가짜 수치 제거)

4.1 IV-space error (업계 표준)

가격 대신 내재 변동성 공간에서 오차 측정. 실무에서 모든 옵션 프라이싱 NN 논문이 이 지표를 우선 보고함.

구현 위치: scripts/bench_nn_pricer.py 에 추가 예정 (§6 체크리스트).
기존 IV 솔버 활용: packages/pricing/src/pricing/iv.py:11 (implied_vol(target_price, BSMInputs, opt))

4.2 Moneyness-stratified 리포트

논문 표 형식 (Horvath 2021 Table 2 참조):

영역범위nMAE (vol pts)p95 (vol pts)
Deep OTMS/K < 0.9~1500▢▢
OTM0.9 ≤ S/K < 0.97~800▢▢
ATM0.97 ≤ S/K ≤ 1.03~500▢▢
ITM1.03 < S/K ≤ 1.10~900▢▢
Deep ITMS/K > 1.10~1300▢▢

4.3 Intrinsic-filter

Call 의 경우 C_true < max(0, S − K·e−rT) + 0.01 인 샘플 제외. 가격이 intrinsic value 바로 위에 있어 의미 없는 영역 (계산 오차·부동소수점 잡음과 구분 안 됨).
