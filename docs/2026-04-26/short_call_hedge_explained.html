Short Call 헤지 — 시각으로 이해하기

작성 2026-04-26 · 대상: 옵션/델타헤지 처음 듣는 사람 · 배경 질문: "헷지가 주식 파는 거 아님?", "왜 daily 임? 초단위여야 하지 않음?"

이 문서가 답하는 3가지
① 누가 short call (콜 매도) 입장에 서나? — 증권사 발행 데스크 (한화·미래·KB 등)
② 왜 헤지가 "주식 사기" 인가? — 발행자는 콜을 팔았고, 콜 가치 ↑ = 손실 이라 주식으로 상쇄
③ 왜 daily? 초단위 아니어야 하나? — 사용자 말이 맞음. 실무는 틱~분, 우리는 학술 표준

1. 누가 콜을 파나 — ELS/워런트 발행 구조

사용자가 흔히 상상하는 옵션 시장은 "내가 SPY 샀고 폭락 보호용으로 풋 사거나, 콜 팔거나" 같은 리테일 투자자 관점 입니다. 우리 시뮬은 그 반대편 — 증권사 발행 데스크 관점 이에요.

1.1 한화증권이 ELS 를 팔면 무슨 일이 벌어지나

혼동 주의 — 두 시나리오 비교
시나리오주체가진 것위험헤지 방향
리테일 투자자개인SPY 주식 주가 ↓주식 팔기 or 풋 사기
우리 시뮬 (=발행 데스크)증권사(복합) 콜 매도 포지션 주가 ↑주식 사기 ← 이게 우리 NN 이 하는 일
옵션 매수자트레이더콜 매수 주가 ↓주식 팔기
같은 "헤지" 라는 단어라도 주체가 다르면 매매 방향이 정반대. 우리는 발행 데스크 관점.

2. 왜 주식을 사는 게 헤지인가 — 수익곡선으로 보기

발행자가 콜을 팔면 손익(PnL)이 주가의 함수로 얼마나 변하는지 그림으로 보면 즉시 이해됩니다.

2.1 숫자로 — 1주 짜리 콜 1개 매도, hedge=0.5 주 보유 케이스

주가 SShort Call PnL주식(0.5주) PnL합계해석
80 (폭락)+5 (프리미엄 챙김)−10−5헤지가 손실
95 (소폭하락)+5−2.5+2.5약간 이익
100 (행사가)+50+5최선 — 프리미엄 그대로
110 (소폭상승)−5 (콜 행사됨)+50완벽 상쇄
130 (폭등)−25+15−10헤지 부족 (0.5 → 1.0 으로 늘렸어야)
핵심: 헤지 비율 0.5 는 "주가가 100 근처에 있을 때만" 잘 작동. 주가가 130 으로 오르면 콜이 무조건 행사되니까 hedge=1.0 (1주 풀 보유) 이어야 함. 이 "비율 조정 룰" 을 NN 이 학습.

3. 왜 daily? — 사용자 말이 맞다, 실무는 틱 단위

사용자 직관 정확합니다. 실시간 옵션 데스크는 daily 안 씀. 우리가 daily 인 이유는 순전히 학술 비교 표준 (Buehler 2019 원논문) 때문.

3.1 리밸런싱 주기별 비교

주기장면장점단점
틱 (~1초) 증권사 마켓메이킹 데스크 (실무) 코비드 폭락도 1초 안에 대응 TC 폭증 + 인프라 (수십억) + 충돌 위험
1분~5분 퀀트 헤지펀드 대부분 fast move 잡음 인프라 비용 + 데이터 양
1시간 리테일 자동매매 감당 가능한 인프라 1시간 내 폭락엔 미대응
1일 (우리 시뮬) 학술 벤치마크 (Buehler 2019) BSM Δ daily 와 직접 비교 가능 → "+24.5% 개선" 의미 명확 코비드 −12% 같은 1일 폭락 통째로 노출
주간 저빈도 헤지펀드 TC 거의 0 위험 매우 큼

3.2 그림으로 — 코비드 −12% 폭락 시 daily vs intraday

3.3 우리 NN 을 1분 단위로 학습 가능한가?

네, 가능합니다. 코드 변경 거의 없음.
  • cfg.n_steps = 30 (1일×30일) → cfg.n_steps = 30 × 390 (1분×30일×6.5시간)
  • cfg.tc_rate = 0.003 (3bp = 30bps) → 더 작게 (실무 spread + impact 모델로 교체)
  • SPY 1분봉 데이터 (yfinance 7일치만 무료, 그 이상은 유료)
단 학습 시간 3,900배 ~ 약 5일 (CPU 기준), GPU 필요. 그리고 TC 모델이 부정확하면 NN 이 "거래 안 하는 게 최선" 으로 수렴 (실무 갭의 핵심).

4. "내일의 헤지" 가 아니라 "다음 step 동안 유지할 헤지"

표현이 헷갈렸으면 미안합니다. 정확한 메커니즘은 이래요.

4.1 그럼 "초단위 즉시 대응" 은 가능한가?

방식대응 속도한계
NN 을 1초 step 으로 학습 1초 단위 헤지 조정 틱 데이터 + GPU + 정교한 TC 모델 필요
이벤트 기반 (변동성 임계 넘을 때만 호출) 밀리초 단위 임계값 튜닝 필요, 노이즈 거래 위험
완전 즉시 (틱 단위 PID) 네트워크 latency 한계 (~1ms) NN 추론 불가, 단순 룰만 가능 (HFT 영역)
현실적 trade-off: 더 짧을수록 위험 ↓ 하지만 거래비용 ↑. 실무 데스크는 "1분 NN 결정 + 변동성 급증시 이벤트 추가호출" 의 hybrid 가 일반적. 우리 NN 도 이렇게 확장 가능 — 알고리즘 자체가 step 길이에 무관하게 작동.

5. 우리 시뮬과 실무 데스크 — 갭 정리

차원우리 시뮬실무 데스크실무 도입 시 추가 작업
시점 주기 1일 1초 ~ 1분 틱 데이터 + step 단축 + GPU 학습
거래비용 (TC) proportional 30bps spread + 시장 충격 (주문 size 의존) order book 기반 TC 모델
유동성 무한 호가 얇음 (특히 KOSPI200 옵션) liquidity-aware action space
상품 단일 콜 옵션 1개, 30일 ELS/Autocallable, basket, KO/KI 다차원 상태 + 경로 의존성
시장 모델 SPY block bootstrap vol regime + 정책 충격 + 만기 효과 regime-switching simulator
실시간 인프라 없음 (offline) tick 처리 + 주문 라우팅 + risk check OMS/EMS 연동, 6개월~1년 R&D

6. TL;DR (비전공자용 한 줄 요약)

  • 누가: 한화증권 같은 ELS 발행자가 콜 매도자 입장 → 주가 ↑ 면 손해
  • 무엇을: 주가가 행사가 근처면 주식 절반 정도 사두고, 행사가 위로 가면 더 사고, 아래로 가면 팜
  • 언제: 우리 시뮬은 1일 1번 (학술 표준), 실무는 틱~1분 (사용자 직관 정답)
  • 왜 NN: 이 "비율 조정 룰" 을 코드 한 줄도 사람이 안 짜고 자동 학습
  • 30% 절감 의미: BSM 교과서 헤지보다 꼬리 손실 1/3 줄임 → 학술 PoC 로는 강력, 실거래는 6개 갭 추가 R&D

8. 용어 정리집

용어한 줄 설명본문에서의 역할
콜옵션 (Call Option) "미래에 정해진 가격(K)에 살 권리" 를 사고파는 계약 발행자가 매도하면 주가 ↑ 시 손실
행사가 (Strike, K) 옵션 계약상 정해진 매매 기준 가격 이 가격을 넘느냐가 행사/소멸을 결정
프리미엄 (Premium) 옵션 매수자가 매도자에게 처음에 지불하는 가격 발행자 입장에서 첫 cash 입금 (premium = 1억 입금)
발행자 (Issuer) ELS/워런트를 만들어 시장에 내는 증권사 경제적으로 옵션 매도자 = 우리 시뮬 주인공
ELS (Equity Linked Securities) 주가 연계 증권. 만기 시 주가 조건에 따라 수익 결정 발행자에게 (복합) 콜 매도와 같은 위험 구조
델타 (Delta) 주가 1원 변할 때 옵션 가치가 몇 원 변하는지 = 헤지로 보유해야 할 주식 수량 (BSM 공식으로 계산)
델타 헤지 옵션의 델타만큼 기초자산을 보유해 위험 상쇄 본 보고서가 다루는 헤지 방식
리밸런싱 (Rebalance) 시간이 지나 변한 델타에 맞춰 주식 보유량을 조정 1일/1분/1초 등 주기에 따라 비용/위험 trade-off
거래비용 (Transaction Cost, TC) 매매할 때 드는 수수료/스프레드 비용 리밸런싱 자주 할수록 누적 폭증, 핵심 trade-off
BSM (Black-Scholes-Merton) 1973년 노벨상 옵션 가격 공식 교과서 헤지의 baseline. NN 이 이걸 이겨야 의미
CVaR@5% "가장 나쁜 5% 시나리오" 의 평균 손실 꼬리 위험 측정치. NN 의 학습 목표
OTM / ATM / ITM 외가격 / 등가격 / 내가격 — 주가 vs 행사가 위치 OTM=무가치 가능성↑, ITM=행사 확실성↑
마켓메이커 (Market Maker) 호가를 양방향으로 띄워 유동성 공급하는 트레이더 실시간 헤지가 본질적 비즈니스 (1초 단위)
