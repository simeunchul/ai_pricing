한 줄 결과 — compliance/explainer_facade.py 신규 모듈로 누적 23 audit_log entries 가 customer 자연어 + regulator 수치 양층 동시 출력. 추후 한화 desk 의 ELS 고객 추천 / 로보어드바이저 영역으로 확장 시 facade.register() 한 줄로 통합.

  • 대신 2-tier explainer 만 가져와서 기존 compliance 모듈에 추가
  • 추후 추천 시스템 추가 시 동일 facade 그대로 차용 가능

3. 어떻게 — 설계 핵심 3가지

A. 결정론적 — LLM 호출 없음

Template 기반 (model_name, stage) → format string. 같은 결정 → 같은 자연어 보장. 감사관이 "왜 이 자연어가 나왔는지" 묻기 어려운 LLM 출력의 비결정성 회피. (추후 LLM 옵션 추가 가능, 지금은 baseline.)

B. Plug-in — 기존 4 audit_log call site 무수정

desk_day.py, bench_lp_strategies.py 의 4곳 audit append 호출은 손대지 않음. facade 는 읽기 전용으로 entry 받아 자연어 생성. 이미 누적된 23 entries 도 사후 enrich 가능.

C. 확장 가능 — register() 한 줄로 신규 모델

# 추후 추천 시스템 추가 시:
facade.register(
    "PLE_distilled_recommender", "recommend",
    lambda e: f"투자 성향 {e.inputs['risk']} → {e.output['top_product']} 추천",
)

regulator: deviation_pct=10.51 breach=False hitl=False output.hedge_ratio=0.4315

④ ETF LP 양방향 호가 (Avellaneda-Stoikov, 재고 한도 임계)

customer: 양방향 호가 bid 71,643.80 / ask 71,715.48, spread 1.29, 재고 -22/20, γ=0.1, 재고 한도 임계 도달 — 보수적 호가.
regulator: deviation_pct=110.0 breach=True hitl=True output.bid=71643.80 output.ask=71715.48 output.spread=1.29

현재 audit log 에 등록되지 않은 (model, stage) 페어가 들어와도 facade 가 안전하게 generic 자연어 생성. template 작성 안 한 모델도 사용자에게 의미 전달 가능.

8. 면접 답안 (예상 질문)

Q: "AI 결정을 고객에게는 어떻게 설명할 건가요?"

A: "audit log 에 모든 AI 결정 (timestamp + 입력 + 출력 + 편차) 기록은 regulator 층 입니다. 그 위에 ExplainerFacade 를 plug-in 해서 customer 층 자연어 동시 생성. 예: ELS NAV 21% breach 가 regulator 에는 'deviation_pct=21.0957 breach=True', 고객에는 '한화 ELS NAV 7,890원, 발행가 대비 +21.10%, KI 확률 67.9%' 로 동시 출력. 결정론적 template 기반 — 감사관이 자연어 출처를 묻기 어려운 LLM 비결정성 회피."
Q: "AI 기본법 시행령 변화 시 대응?"

A: "compliance 모듈에 4종 가드 (audit + deviation + HITL + 2-tier) 가 baseline. 시행령이 추천 시스템 / 알고리즘 거래 / ELS pricing 을 명시 고영향으로 분류해도 facade.register() 한 줄로 신규 모델 추가만 하면 됨. 모듈성 + 확장성 입증."
Q: "왜 LLM 안 썼나요?"

A: "감사관이 '왜 이 자연어가 나왔는지' 묻을 때 결정론적 template 은 1:1 추적 가능. LLM 출력은 동일 입력에서도 다른 결과 → 감사 곤란. baseline 은 결정론적, 고객 다양성 필요 시 LLM layer 추가는 별도 스프린트."
