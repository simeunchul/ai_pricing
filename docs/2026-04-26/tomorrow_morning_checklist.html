찾아볼 패턴

로그 패턴의미대응
"sig":"BUY" 또는 "SELL" 매매 발생 order_response 의 rt_cd=0 인지 확인
"dev_bps":+/- 30 이상 iNAV 괴리 진입 임계 도달 signal 발생 정상
basket coverage X% — signal forced HOLD 구성종목 시세 일부 fail tolerance 동작. 안전 (50% 이하 fresh 시 매매 안 함)
risk halt: outside trading hours 09:10 이전 또는 15:20 이후 정상 (시간 가드 작동)
tick N error: HTTPError 일시 API 장애 9회 누적 시 자동 종료. 재시작 필요

6. 가능한 시나리오 + 대응

#시나리오대응
1 매매 신호 한 번도 안 발생 (HOLD 만) 정상. KOSPI 대형 ETF 평소 5~15bps. 30bps 임계 못 넘김. "정상적인 LP가 잘 작동하는 시장" 의 증거.
2 basket coverage 50% 미만 자주 모의투자 시세 한계. enter_threshold 보수적으로 조정 또는 ETF 만 보고 단순 mean-revert.
3 매매 발생 후 손실 누적 −1.5% 자동 정지 (risk guard). 다음날 재시작.
4 API 9회 연속 에러 → 종료 네트워크 / KIS 장애. 잠시 후 재시작.
5 실주문 endpoint reject (rt_cd != 0) 예수금 부족, 매매 정지 종목 등. 로그 msg1 확인 + KIS HTS 로 잔고 직접 확인.
