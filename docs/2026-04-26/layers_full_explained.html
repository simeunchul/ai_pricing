A Layer A — Classical Pricing (고전 투자공학)

한 줄 정의: 100년에 걸쳐 다듬어진 수학 공식으로 옵션 가격을 계산합니다. "AI 없이 종이와 연필로 풀 수 있는" 방법론입니다.

A-1. 무엇을 하는가

5개 모듈로 구성됩니다. 각각 가격을 계산하는 다른 방식입니다:
모듈방식장점단점

A-2. 어떤 데이터가 들어오는가

가장 단순한 BSM의 입력은 5개 숫자입니다 ([bsm.py:11-24](packages/pricing/src/pricing/bsm.py#L11-L24)): 
@dataclass(frozen=True)
class BSMInputs:
    S: float       # 현재 주가          예: 100원
    K: float       # 행사가              예: 100원
    T: float       # 만기까지 시간(년)    예: 0.25 (3개월)
    r: float       # 무위험 이자율        예: 0.03 (3%)
    q: float       # 배당 수익률          예: 0.0
    sigma: float   # 변동성              예: 0.20 (20%)

A-3. 어떻게 계산하는가 — BSM 공식

실제 코드 ([bsm.py:42-46](packages/pricing/src/pricing/bsm.py#L42-L46)): 
def call_price(i: BSMInputs) -> float:
    if i.T == 0:
        return max(i.S - i.K, 0.0)              # 만기 시 페이오프
    d1, d2 = _d1_d2(i)
    return i.S * math.exp(-i.q * i.T) * norm.cdf(d1) \
         - i.K * math.exp(-i.r * i.T) * norm.cdf(d2)

A-4. Heston은 왜 더 복잡한가

BSM은 변동성 σ를 고정 상수로 봅니다. 그런데 현실에서 변동성은 변합니다. Heston은 변동성 자체도 확률과정으로 모델링합니다 ([heston.py:23-29](packages/pricing/src/pricing/heston.py#L23-L29)): 
@dataclass(frozen=True)
class HestonParams:
    kappa: float   # κ: 변동성이 평균으로 회귀하는 속도
    theta: float   # θ: 장기 평균 변동성²
    xi: float      # ξ: "변동성의 변동성"
    rho: float     # ρ: 주가-변동성 상관관계 (보통 음수: 주가↓이면 변동성↑)
    v0: float      # 현재 변동성²
Heston의 대가: 5개 파라미터(κ, θ, ξ, ρ, v₀)가 모두 미지수입니다. "이 5개를 어떻게 정하느냐?"가 바로 Layer B2 (Deep Calibration)가 푸는 문제입니다.

A-5. Step-Down ELS — 한국 시장 핵심

ELS(주가연계증권)는 한국 개인 투자자가 가장 많이 사는 파생상품입니다. 구조는 6개월마다 조기상환 조건을 점검하는 "Step-Down" 방식이 표준입니다 ([step_down.py:19-31](packages/pricing/src/pricing/els/step_down.py#L19-L31)):

코드는 50,000개 경로를 시뮬레이션해 (평균 가격, 조기상환 확률, KI 적중률, 기대 만기) 를 반환합니다 ([step_down.py:43-126](packages/pricing/src/pricing/els/step_down.py#L43-L126)).

A-6. 결과로 무엇이 나오는가

  • 가격 (예: 콜 옵션 4.62원) — Layer C가 다른 모델과 비교
  • 그릭스 (Δ, Γ, ν 등) — Layer B4의 BSM 헤지 베이스라인이 사용

B1 Layer B1 — NN Pricer (가격을 신경망이 학습)

한 줄 정의: BSM 공식을 신경망이 따라하게 학습. 정확도는 비슷하지만 호출 속도가 수천 배 빨라집니다.

B1-1. 왜 신경망이 필요한가

BSM 공식은 한 번 계산이 0.1ms 정도. 하루에 수천 종목 × 수백 호가 × 실시간 = 초당 100만 회 이상 호출이 필요한 시장조성·HFT에서는 너무 느립니다. NN은 GPU에서 배치로 한꺼번에 계산해 0.0001ms 수준으로 떨어뜨립니다.

B1-2. 입력 → 출력 구조

코드 ([model.py:37-59](packages/ai_pricing/src/ai_pricing/nn_pricer/model.py#L37-L59)): 
class NNPricer(nn.Module):
    """MLP: [logM, T, r, q, sigma] → C/K."""
    def __init__(self, cfg):
        ...
        layers = []
        in_dim = 5
        for h in (128, 128, 64):
            layers += [nn.Linear(in_dim, h), nn.Tanh()]
            in_dim = h
        layers += [nn.Linear(in_dim, 1), nn.Softplus()]  # 가격 > 0 보장
        self.net = nn.Sequential(*layers)

B1-4. log-MSE 손실의 이유 — 기억해야 할 함정

중요: 메모리 feedback_nn_training.md에 기록된 함정 — 일반 MSE를 쓰면 deep OTM 가격(거의 0)을 무시하고 지표만 좋아 보입니다. log-MSE 또는 hybrid loss로 학습해야 양 끝단까지 정확합니다.
학습 손실 차이를 비교한 표 ([train.py:32-63](packages/ai_pricing/src/ai_pricing/nn_pricer/train.py#L32-L63)):
손실수식 핵심장점문제
MSE (원형)(pred − y)²단순큰 가격에만 집중, OTM 무시
rel-MSE((pred-y)/y)²상대오차 균형y≈0 근처 폭주 ❌
log-MSE ✅(log pred − log y)²스케일 불변, 양 끝 안정Deep ITM은 약간 양보
hybridα·log-MSE + (1−α)·MSE두 장점 결합α 튜닝 필요

B2 Layer B2 — Deep Calibration (시장 → 모델 역추정)

한 줄 정의: 시장에서 관찰되는 변동성 곡면(IV surface)을 보고, 이걸 만들어낸 Heston 5개 파라미터를 거꾸로 찾아냅니다.

B2-1. 왜 필요한가

Heston 공식을 쓰려면 (κ, θ, ξ, ρ, v₀) 5개를 알아야 합니다. 그런데 시장에는 가격(또는 IV)만 있습니다. "이 IV 곡면을 만들어내는 Heston 파라미터는 무엇인가?"를 푸는 게 캘리브레이션입니다. 전통적으로는 비선형 최적화로 푸는데 1회당 30초~수 분. NN으로 사전 학습하면 1초 이내에 끝납니다 (Horvath et al. 2021).

B2-2. 데이터 흐름

B2-3. 입력 데이터 — IV 곡면이란

theta = torch.tensor(init, requires_grad=True)   # (κ,θ,ξ,ρ,v₀) 5개를 변수로
opt = torch.optim.Adam([theta], lr=5e-2)

for _ in range(300):
    pred = model(theta) * y_std + y_mean         # NN으로 IV surface 예측
    loss = torch.mean((pred - target) ** 2)      # 시장과 비교
    loss.backward()
    opt.step()
    theta.data = clamp(theta.data, lo, hi)       # 박스 제약

B4 Layer B4 — Deep Hedging (RL로 헤지 학습)

한 줄 정의: 옵션을 판 발행자(증권사)가 거래비용까지 고려한 최적 헤지 전략을 강화학습으로 직접 학습합니다. BSM 델타 헤지보다 비용을 줄입니다.

B4-1. 핵심 문제 — 왜 BSM 델타로는 부족한가

BSM 델타 헤지는 "거래비용 0, 무한히 자주 리밸런싱" 가정 하에서만 정확합니다. 현실에서는:
  1. 매매할 때마다 수수료/슬리피지 발생
  2. 너무 자주 리밸런싱하면 → 비용 폭증
  3. 너무 드물게 → 헤지 오차 누적
이 trade-off의 최적점을 RL이 데이터로 직접 찾습니다.

B4-3. 성공 방법 — Buehler 2019 직접 구현

핵심 아이디어 ([buehler_pg.py:1-16](packages/ai_hedging/src/ai_hedging/agents/buehler_pg.py#L1-L16)): 
# 핵심: 환경(Gym) 안 쓴다. 전체 시뮬레이션을 PyTorch 텐서로!
# → 정책의 출력 → S 경로 → terminal pnl → CVaR 까지 그래디언트 직통

def simulate_batch(policy, cfg, batch_size):
    S = torch.full((B,), cfg.S0)              # 초기 주가 (텐서!)
    cash = torch.full((B,), premium)          # 받은 프리미엄
    hedge = torch.zeros(B)
    for t in range(cfg.n_steps):
        obs = build_state(S, cash, hedge, t)
        new_hedge = policy(obs)               # NN 정책 (미분가능)
        tc = cfg.tc_rate * |new_hedge - hedge| * S
        Z = torch.randn(B)                    # GBM 노이즈
        S = S * exp(drift_dt + diff_dt * Z)
        cash = cash * exp(r·dt) + new_hedge*(S_next - S) - tc
    payoff = relu(S - cfg.K)
    return cash - payoff                       # terminal pnl, 그래디언트 살아있음

# 학습
pnl = simulate_batch(policy, cfg, 4096)
loss = -pnl.sort()[:int(0.05 * 4096)].mean()  # CVaR_5%: 최악 5%의 평균 손실
loss.backward()                                # → policy 업데이트

B4-4. CVaR 손실 — 왜 이게 핵심인가

왜 평균 손실이 아니라 CVaR? 평균만 줄이면 "대부분 좋은데 가끔 큰 손실"이 허용됩니다. CVaR은 꼬리(최악의 시나리오) 자체를 줄입니다. 한화 같은 발행사는 "최악의 날 얼마 잃을까"가 더 중요합니다.

D-2. 매매 로직

핵심 코드 ([etf_inav_arb.py:33-45](packages/autotrader/src/autotrader/strategies/etf_inav_arb.py#L33-L45)): 
class EtfInavArbitrage:
    enter_threshold: float = 0.003   # 30 bps (0.3%) 괴리시 진입
    exit_threshold:  float = 0.0005  # 5 bps 이내로 좁혀지면 청산

    def decide(self, deviation):
        if self.position == 0:
            if deviation < -0.003:  return BUY     # ETF가 iNAV보다 0.3% 이상 싸다 → 매수
            if deviation > +0.003:  return SELL    # 0.3% 이상 비싸다 → 매도
        elif self.position > 0 and deviation > -0.0005:
            return SELL                            # 청산
        return HOLD

📋 비전공자용 TL;DR

  1. 옵션 가격은 미래 주가 분포의 기댓값을 현재가치로 할인한 것입니다. Layer A는 이걸 수학 공식으로 계산합니다.
  2. 같은 가격을 NN으로 학습하면 빨라집니다 (B1) — 실시간 호가용.
  3. 시장 데이터로부터 모델 파라미터를 거꾸로 찾는 건 NN이 잘합니다 (B2) — 캘리브레이션.
  4. 뉴스를 읽고 변동성을 보정해 가격을 바꾸는 것도 가능합니다 (B3) — 정보 우위.
  5. 발행사가 옵션을 헤지할 때 거래비용을 고려한 최적 정책을 RL이 직접 학습합니다 (B4) — 헤지 비용 −24.5%.
  6. 이 5가지를 같은 옵션에 적용해 비교하는 게 Layer C — 의사결정 1차 게이트.
  7. 별도로 ETF 자동매매는 Layer D — 옵션과 무관한 트랙.
  8. 몬테카를로 가속은 Layer E — C++ 60배 더 빠름.

용어한 줄 설명본문에서의 역할

콜 / 풋콜=살 권리, 풋=팔 권리BSM 공식이 두 종류 모두 계산
S, K, T, r, q, σ현재가, 행사가, 만기, 금리, 배당, 변동성BSM 입력 6개 — 모든 Layer가 공유

IV (Implied Volatility)"시장가가 맞다고 가정할 때 역산한 σ"B2/B3에서 가격 대신 사용
