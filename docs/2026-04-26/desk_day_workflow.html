1. 무엇을 시도했는지 (배경 + 접근)

왜 "데스크의 하루" 프레이밍인가

지금까지 5-Layer (A/B1/B2/B3/B4 + C·D·E) 산출물은 "5가지 가격 모델 비교" 라는 학술 프레이밍으로 묶여 있었다. 이 프레임은 면접관에게 "성실하게 모듈을 만든 학생" 으로 보일 뿐, "한화 디지털금융 Trading 데스크에 들어와도 일할 수 있는 사람" 으로는 안 보인다.

같은 코드를 "한화 ELS 데스크의 하루 — 09:00 calibration → 16:30 PnL" 시간 순 워크플로우로 재배치하면, 면접관 1분 설명에 즉시 실무자 시각으로 보인다. Focal product 는 이미 보유한 실 공시 데이터인 한화스마트ELS 제8286호 (3자산 worst-of step-down: KOSPI200 / SPX / SX5E, 3Y, 11.31% 쿠폰).

접근 — orchestration 스크립트가 시간 순으로 실제 layers 호출

보고서만 새로 쓰면 "branding-only" 함정. 신뢰 만들려면 scripts/desk_day.py 가 7 stage 를 시간 순으로 chain 하고 실 코드 호출 결과가 본 보고서의 timeline 으로 흘러 들어와야 한다. 본 보고서 모든 수치는 실제 desk_day.py 실행 결과 (data/desk_day/run_2026-04-26.json) 직접 인용.

★ 시각 3 메타박스 — "왜 이 데스크는 PPO 가 아닌 Buehler 를 쓰는가" (5번 실패 일지)

데스크의 헤지 알고리즘 채택 결정 일지. PPO 5종 시도 모두 실패 후 Buehler 2019 원논문의 "PG-on-CVaR direct backward" 채택. 자세히는 why_dh_failed.html + B4_buehler_implementation.html.

시도설명결과
v1 vanilla PPOSB3 PPO + MlpPolicy + GBM env−1100% CVaR (entropy collapse)
v2 action clip + reward shapingaction box [0,1] + per-step Δ-mimic shaping+7.8% — best PPO, PARTIAL
v3 longer training200k → 800k steps+2% — entropy still collapsed
v3b BC warm startBSM Δ behavior cloning + PPO fine-tune+1% — BSM attractor lock
v3c residual to BSMaction = Δ_BSM + residual+0.5% — converges to BSM exactly
Buehler PG-on-CVaR direct (현재)gym 폐기 + PyTorch differentiable simulator + CVaR loss 직접 backward+24.5% (GBM) / +31.3% (SPY historical) PASS

본질 진단: PPO 의 max E[Σ reward] 와 우리 목적 min CVaR_5%[loss] 는 직교 함수. Buehler 원논문이 gym/PPO 안 쓴 이유를 5번 실패 후 정확히 이해. 이 데스크는 그 학습 포인트를 코드에 박아 둔 것.

7. 비전공자용 요약 (TL;DR)

  1. 지금까지 만든 5-Layer 결과를 "5가지 가격 모델 비교" → "한화 ELS 데스크의 하루" narrative 로 재배치. 같은 코드인데 09:00 ~ 16:30 시간 순으로 chain 되니 "이 사람이 정말 데스크 워크플로우를 이해하고 있구나" 신호가 즉시 들어옴.
  2. desk_day.py 가 실제로 7 stage 함수를 시간 순으로 호출하고 결과를 JSON 으로 dump. 보고서의 모든 수치는 그 실행 결과 직접 인용 — branding 만 입힌 게 아니라 코드가 진짜 시간 순으로 돈다.
  3. 13:00 hedge 시점에 시각 3 메타박스 — "이 데스크는 왜 PPO 가 아닌 Buehler 를 쓰는가" 5번 실패 디버깅 일지를 한 칸에 정리. 면접에서 "헤지 알고리즘 어떻게 골랐냐" 질문 즉답 가능.
  4. AI 기본법 (2026-01-22 시행) 자발적 대응 도 코드에 통합: 모든 AI 모델 의사결정 JSON 로그 + BSM 기준 ±5% 편차 자동 모니터링 + HITL gate 3종. 오늘 실행에서 3 decision 기록, 2 deviation breach, 2 HITL escalate.
  5. 한 줄 면접 답변: "한화 ELS 데스크에 들어오면 이 desk_day.py 의 7 stage 가 매일 09:00 ~ 16:30 자동 실행되고, AI 모델 출력이 BSM 기준에서 벗어나면 즉시 trader 에게 escalate. 그래서 회색지대 영역에서도 안전 baseline."
