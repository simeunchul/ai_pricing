3. 두 번째 원인 — Dense reward shaping 의 BSM attractor

우리가 사용한 reward 의 dense 부분:

shape_reward = −λ × (V_hedge_change − V_option_change)²

이 함수의 minimum (=0) 위치는?

BSM Δ 헤지 정확히 = V_hedge_change 가 V_option_change 와 같아지는 지점.
즉 PPO 가 reward 최대화하면 자동으로 BSM Δ 로 끌려감.

5. 진짜 답 — 4가지 알고리즘 변경 경로

방법핵심 변경예상 작업량플랜 20% 가능?
(a) CVaR surrogate loss reward 자체를 CVaR 의 미분가능 근사로 (Rockafellar-Uryasev 1999 distortion measure). PPO 의 advantage 계산 modify. ~1일 ✓ 가장 직접적
(b) SAC + Quantile regression Distributional RL. policy 가 reward 분포 자체를 학습 → tail 직접 access 가능. ~2일 ✓ 학술적 정통
(c) Buehler 2019 직접 구현 policy gradient 를 CVaR loss 에 직접 적용. PPO 안 씀. 원논문이 한 방식. ~1일 ✓ 원논문 재현
(d) Imitation only + 인위적 under-hedge RL 빼고 rule-based heuristic. BC 로 BSM Δ 100% 모방, inference 시 hedge × (1−α) 곱하기. α≈0.1~0.3. ~3시간 ? 단순하지만 효과 검증 필요
실용적 추천:
• (d) 부터 — 알고리즘 복잡도 0, 실무 효과 측정 가능. 면접 자리에서 "PPO 한계 발견 후 가장 단순한 우회까지 시도" narrative 가 강함.
• 시간 여유 있으면 (c) 가 학술적으로 정확. Buehler 원논문 그대로 재현.
• (b) 는 별도 R&D 트랙으로.

6. 면접 자리 talking points

예상 질문 1: "왜 Deep Hedging 이 BSM 못 이겼나요?"

답안: "PPO 는 expected reward 최대화 알고리즘인데 우리가 원한 건 CVaR 최소화. 두 함수가 직교합니다. 추가로 dense shaping reward 의 minimum 이 정확히 BSM Δ 위치라 학습 길어질수록 BSM 에 끌려갑니다. 이게 hyperparameter 문제가 아니라 알고리즘 설계 자체의 한계라는 걸 5번 시도(v2/v3/v3b/v3c/residual) 후 진단했고, Buehler 2019 원논문도 PPO 안 쓰고 policy gradient 를 CVaR 에 직접 적용한 이유가 명확해졌습니다."
예상 질문 2: "5번 실패가 부끄럽지 않나요?"

답안: "vanilla PPO 한 번 succeed 보다 5번 실패 후 정확한 진단까지 도달한 것이 더 깊은 학습입니다. 실무에서도 잘못된 알고리즘 선택을 6개월 끌고 가는 것보다 빨리 진단하고 알고리즘 변경하는 게 비용 적습니다. 지금 저는 SAC distributional 또는 Buehler 직접 구현으로 가야 한다는 명확한 다음 단계를 가지고 있습니다."
예상 질문 3: "그럼 결국 BSM Δ 가 답이라는 건가요?"

답안: "거래비용 0인 합성 GBM 환경에서는 BSM Δ 가 이론적으로 optimal 이 맞습니다. 하지만 TC>0 또는 jump-diffusion 같은 실시장 환경에서는 BSM Δ 가 약화됩니다. 그래서 Deep Hedging 이 의미 있어지는 곳은 합성 GBM 이 아니라 실시장 historical path 입니다. 다음 단계는 이 환경 자체를 GBM 에서 historical replay 로 바꾸는 것입니다."
