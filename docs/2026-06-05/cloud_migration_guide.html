2026-06-05 · ARM Ampere A1.Flex (영구 무료) · Seoul region · Ubuntu 22.04 · systemd 기반

한 줄 결과. 데스크톱 PC 종속 운영의 가장 큰 한계 — "PC 가 꺼지면 봇도 죽음" — 을 영구 해결. Oracle Cloud Always Free 의 Seoul 리전 ARM 인스턴스를 사용하면 월 0원으로 4 OCPU + 24 GB RAM 까지 영구 무료, 24시간 KIS API 접근 가능. systemd 가 Windows 작업스케줄러 + watchdog 둘을 한 번에 대체.

2. 사전 준비 (사용자 작업)

이 단계는 사용자가 직접 해야 합니다. Claude 가 Oracle 계정 접근권 없음.
STEP 1

Oracle Cloud 계정 생성

  1. https://www.oracle.com/cloud/free/ 접속 → "Start for free"
  2. 이메일 + 한국 휴대폰 번호로 인증
  3. 이름·주소 입력 (영문 권장 — 이후 영문 인보이스에 사용됨)
  4. 신용카드 등록 (실제 청구 없음, 본인 확인용) — Visa/Master 권장
  5. 가입 완료까지 약 15분 — Oracle 측 검토에 따라 최대 1-2일 걸릴 수 있음
STEP 2

SSH 키 생성 (로컬 PowerShell)

Windows 에서 키페어 만들기:

ssh-keygen -t rsa -b 4096 -f $HOME\.ssh\oracle_kis

두 파일이 생성됨:

  • oracle_kis — private key (절대 공개 금지)
  • oracle_kis.pub — public key (VM 에 등록할 것)
STEP 3

Compute Instance 생성

  1. Oracle Cloud Console → 좌측 메뉴 → Compute → Instances → "Create instance"
  2. Image: Canonical Ubuntu 22.04 (ARM 용 — ARM Build 명시된 것 선택)
  3. Shape: VM.Standard.A1.Flex (Ampere) — OCPU 1, Memory 6 GB
  4. Networking:
    • VCN 자동 생성 OK
    • Subnet: Public
    • "Assign a public IPv4 address" 체크
  5. SSH keys: "Paste public keys" 선택 → oracle_kis.pub 내용 붙여넣기
  6. "Create" 클릭 → 약 1분이면 Running
Always Free 한도. ARM A1 의 한도는 OCPU 4개 + RAM 24GB 총합까지 무료. 우리는 1+6 만 쓰니 여유 있음. Storage 200GB Block + 10TB outbound 도 무료.
STEP 4

방화벽 — Dashboard 접속 허용

Oracle Cloud Console 의 Security List 에 8501 포트 추가:

  1. 좌측 메뉴 → Networking → VCN → 해당 VCN 클릭 → Security Lists → Default
  2. Ingress Rules → Add Ingress Rules:
    • Source CIDR: 0.0.0.0/0 (전체 — 또는 본인 IP만)
    • IP Protocol: TCP
    • Destination Port: 8501
STEP 5

VM에 SSH 접속

Instance 의 public IP 확인 (예: 132.226.xxx.xxx):

ssh -i $HOME\.ssh\oracle_kis ubuntu@132.226.xxx.xxx

처음 접속 시 "Are you sure you want to continue connecting" → yes.

3. 자동 배포 (VM 에서)

한 줄 deployment. 위 단계까지 끝났으면 VM 에서 setup.sh 한 번 실행으로 모든 설치·설정 자동화.
STEP 6

Setup 스크립트 실행

wget https://raw.githubusercontent.com/simeunchul/ai_pricing/master/deploy/oracle-cloud/setup.sh
chmod +x setup.sh
./setup.sh

이 스크립트가 하는 일:

  1. 시스템 패키지 업데이트 + python3-venv 설치
  2. Timezone 을 Asia/Seoul 로 설정
  3. Repo clone 후 venv 생성
  4. 핵심 의존성 설치 (requests, pandas, numpy, pyarrow, streamlit)
  5. .env 템플릿 생성
  6. systemd 서비스 등록 + enable (자동 시작)
  7. iptables 8501 포트 허용

완료 메시지 보일 때까지 약 3-5분.

STEP 7

KIS 키 입력 (.env 편집)

vi /home/ubuntu/ai_pricing/.env

내용을 다음처럼 채움:

KIS_ENV=vts
KIS_APP_KEY=실제_KIS_APP_KEY
KIS_APP_SECRET=실제_KIS_APP_SECRET
KIS_ACCOUNT_NO=실제_8자리_계좌
KIS_ACCOUNT_PROD=01
KIS_DRY_RUN=false

저장: :wq. 권한 확인:

chmod 600 /home/ubuntu/ai_pricing/.env
STEP 8

서비스 시작

sudo systemctl start dual-bot dual-dashboard eod-reconcile.timer

상태 확인:

systemctl status dual-bot
systemctl status dual-dashboard
systemctl list-timers eod-reconcile.timer

로그 실시간 확인:

journalctl -u dual-bot -f

봇이 "KIS env=vts" 출력하고 "Watch 모드 시작" 메시지 나오면 성공.

STEP 9

Dashboard 접속

브라우저로:

http://<VM 공인 IP>:8501

State + history + trades 가 보이면 모든 게 동작 중.

5. systemd 의 자동복구 — Windows watchdog 대체

Windows 운영 시: 별도 watchdog_dual_runner.py + 5분 주기 작업 스케줄러 + Startup 폴더 .bat. 즉 3-layer 복구 메커니즘.

systemd 는 이걸 모두 자동:

이벤트systemd 동작
봇이 crashRestart=always → 10초 후 자동 재기동
VM rebootWantedBy=multi-user.target → 부팅 직후 자동 기동
봇이 메모리 1GB 초과MemoryMax=1G → OOM kill → Restart 발동
네트워크 끊김After=network-online.target → 네트워크 복구 대기 후 기동
코드 단순화. 클라우드에선 watchdog 스크립트 자체가 불필요. 거기서 발생한 인코딩 버그(2026-06-01) 같은 잠재 문제 자체가 없어짐. "less code = less bugs" 의 정석.

7. 자주 발생하는 문제

봇이 KIS 키 못 읽음

journalctl -u dual-bot -n 20 | grep -i "KIS_APP_KEY"

해결: .env 파일 권한 확인 — chmod 600 /home/ubuntu/ai_pricing/.env. ubuntu 사용자 소유여야 함. ls -la /home/ubuntu/ai_pricing/.env.

Dashboard 접속 안 됨 (Connection refused)

  1. VM 내부 — streamlit 살아있는지: sudo systemctl status dual-dashboard
  2. iptables — 8501 허용: sudo iptables -L INPUT -n | grep 8501
  3. Oracle Console — Security List 에 8501 추가됐는지 (STEP 4)

봇이 계속 죽음 (Restart loop)

journalctl -u dual-bot -n 100 --no-pager

가장 흔한 원인:

  • 의존성 누락 — pip install -r requirements.txt 다시
  • KIS 토큰 만료 — 새로 발급
  • data 디렉토리 권한 — sudo chown -R ubuntu:ubuntu /home/ubuntu/ai_pricing

krx_cache 비어 있음 (모멘텀 신호 안 뜸)

현재 코드는 data/krx_cache/ 의 일별 데이터로 모멘텀 계산. 마이그레이션 시 이 디렉토리는 데이터 없이 시작. 해결: 로컬 PC 의 krx_cache 를 VM 으로 SCP 복사.

scp -i $HOME\.ssh\oracle_kis -r d:\simeunchul\ai_pricing\data\krx_cache ubuntu@<VM IP>:/home/ubuntu/ai_pricing/data/

8. 비전공자용 요약 (TL;DR)

  • Oracle Cloud Always Free 의 ARM 인스턴스를 Seoul 리전에 만든다 — 영구 무료, 신용카드 등록만 필요(과금 X).
  • VM 에 SSH 접속해서 setup.sh 한 번 실행하면 — Python, 의존성, systemd 서비스, 방화벽까지 자동 설정.
  • .env 에 KIS 키 입력 → sudo systemctl start dual-bot → 끝.
  • systemd 의 Restart=always 가 Windows watchdog 을 완전히 대체. 봇 죽으면 10초 안에 다시 살아남.
  • 운영 비용 ₩0, 가동률 99.9%, "프로덕션 grade" 인터뷰 narrative 확보.
