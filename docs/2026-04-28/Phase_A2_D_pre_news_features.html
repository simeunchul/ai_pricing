Phase A2-D — pre-news momentum/sentiment features 로 R² 끌어올리기

2026-04-28 · ai_pricing/autotrader · Phase A 2차 반복

한 줄 결과. 사용자 직감대로 historical 데이터로 LGBM 학습. 첫 시도 (event-only features) 는 Test R² ±0 — baseline 못 이김. D 패키지 추가 (강화 sentiment lexicon + 뉴스 직전 5/15/30분 momentum/volume) 후 Test R² +0.037, baseline 대비 RMSE +4.5% 개선. Feature importance top 2 가 vol_30m, momentum_30m — 뉴스 자체보다 "뉴스 직전 시장 반응" 이 더 informative. Hook + decide_with_fair 까지 인터페이스 완성, 31/31 test pass. Prod 연결은 walk-forward 검증 후.

2. D 패키지 — 무엇을 추가했나

2-1. 강화 sentiment lexicon

기존 classify_rule 은 7-class one-hot (earnings_beat / mna / regulatory / ...) 만 출력. D 에선 긍정/부정 키워드 가중 산술합으로 [-1, +1] 연속값 sentiment_score 추가.

긍정 키워드 (가중치):
  어닝서프라이즈 +1.0, 사상최대 +1.0, 신고가 +1.0, 폭등 +1.0
  호조 +0.6, 상향 +0.6, 수주 +0.6, 매수 +0.6
  반등/회복 +0.4, 성장/증가 +0.3 ...

부정 키워드:
  어닝쇼크 -1.0, 급락 -1.0, 폭락 -1.0, 적자전환 -1.0
  부진 -0.6, 하향 -0.6, 매도 -0.6, 규제 -0.5
  리콜/결함 -0.7, 과징금 -0.7, 전쟁 -0.8 ...

sentiment_score = clamp(-1, +1, (Σpos - Σneg) / √n_words)

2-2. Pre-news momentum / volume features

뉴스가 발생한 시점 직전 5/15/30분 시장 반응 — KIS 5분봉에서 추출.

Feature의미

momentum_15m직전 3 bars (15분) 가격 변화율
momentum_30m직전 6 bars (30분) 가격 변화율

핵심 가정: "뉴스 발표 전 시장이 이미 움직이고 있으면, 발표 후 1시간도 같은 방향" — smart money 의 사전 정보 흡수. look-ahead bias 가 아님 (뉴스 발생 시점 전 데이터만 사용).

4. 정직한 한계

무엇이 효과 있었나: pre-news momentum/vol 이 진짜 신호. 시장이 이미 반응 중일 때 1시간 후 방향 예측 가능.

무엇이 효과 없었나:
  • sent_score (lexicon) 거의 importance 0 — 키워드 매칭이 너무 sparse, 의미 파악 X
  • event_id (rule classifier 7-class) 도 importance 0 — 너무 coarse
  • FinBERT-Ko 시도했으나 torch 보안 이슈로 로드 실패 (CVE-2025-32434)
최종 R² +0.037 = 분산의 3.7% 만 설명. 매우 작은 알파. 실거래 PnL 영향 미지수. 이 모델 단독으로는 prod 운영 비추천, basket-only 와 30:70 ensemble 권장.

005930 (삼성전자) 누락 문제

KOSPI 200 의 30% 비중인 삼성전자가 학습 데이터에서 빠짐. 원인:

  • Naver Search API sort=date 가 최근 1000+1000 = ~5일치만 줌
  • 그 5일이 우연히 weekend 위주 (4/24~4/28 중 4/25토, 4/26일, 4/28월)
  • 장중 거래일 뉴스가 0건 → backtest 0 trades

차후 fix: Naver API 의 sort=sim + 다양한 검색어 조합으로 더 긴 history 확보. 또는 다른 데이터 소스 (한경, 매경 RSS, DART 공시).

5. 봇 통합 인터페이스 (A4)

모델이 baseline 이김 → prod 통합 시그너처 정의. 실제 wiring 은 walk-forward 검증 통과 후.

Runner main loop (매 N분) │ ▼ pricer.maybe_refresh(now, news_by_ticker, # 종목별 최근 뉴스 bars_by_ticker) # 종목별 5-min bars │ → 모델로 종목별 1-hour return 예측 ▼ per ETF symbol: fair_dev = pricer.fair_dev(etf_sym) # 비중 가중 합 │ ▼ strategy.decide_with_fair( dev_basket=current_obs_dev, fair_dev=fair_dev, fair_blend=0.3, # basket 70% + fair 30% ensemble ) → decide_aggressive(combined_dev) 호출 │ ▼ (Signal, qty, use_inverse) — 기존 매매 로직
# strategies/etf_inav_arb.py 에 새로 추가
def decide_with_fair(self, dev_basket, fair_dev, fair_blend=0.3):
    combined = dev_basket * (1 - fair_blend) + fair_dev * fair_blend
    return self.decide_aggressive(combined)

테스트 31/31 통과. fair_blend=0 시 기존 동작과 100% 동일 (안전 fallback).

6. 비전공자용 요약 (TL;DR)

  • 지난번엔 데이터 부족으로 모델이 외워버렸음 (overfit). 그래서 한 달치 historical 12K rows 가져와서 다시 학습.
  • 처음엔 features 가 약해서 (event 분류 + 시간만) 데이터 늘려도 모델이 baseline 못 이김.
  • "뉴스 직전 시장이 어떻게 움직이고 있었나" 추가하니 baseline 4.5% 이김. 모델이 진짜 뭔가 학습.
  • 가장 중요한 feature: vol_30m (직전 30분 변동성), momentum_30m (직전 30분 가격 변화율). 즉 "smart money 가 이미 움직였으면 그쪽으로 가더라" 가설 확인.
  • Sentiment 키워드 사전은 효과 없음 — 단어 매칭 너무 약함. FinBERT-Ko 또는 Claude API 가 진짜 답인데 둘 다 이번엔 못 씀 (torch 보안 이슈/유료).
  • 모델은 "약한 알파" — 봇 결정에 30% 가중으로 ensemble 가능, 단독 사용은 무리. prod 연결은 walk-forward 검증 후.
