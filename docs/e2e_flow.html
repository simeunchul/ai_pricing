1. 프로젝트 의도

문제 정의

한화투자증권 디지털금융(Trading) 직무는 JD 에서 4축을 요구: (1) 자산운용 · (2) ELS 헤지 · (3) ETF LP 업무 · (4) Trading 전산 시스템.

퀀트/파생 경력 없이 이 JD 4축을 포트폴리오 한 건으로 커버하려면 동일 주제를 여러 각도로 풀어내는 모노레포 가 가장 밀도 높은 증명. 그래서 "같은 옵션에 대해 5가지 가격을 산출하고 비교" 를 중심 축으로 잡음.

프로젝트가 증명하려는 것

  1. Classical 퀀트 재현 능력 — BSM, Heston, ELS MC 를 이론서 수준으로 구현하고 검증
  2. AI 응용 능력 — Hutchinson 1994 / Horvath 2021 / Buehler 2019 세 논문 재현
  3. Trading 전산 감각 — 실시간 자동매매 risk guard 설계
  4. 퍼포먼스 엔지니어링 — Python 병목을 C++ 로 밀어내는 습관
  5. 실험 설계 — 동일 경로에서 5 method 비교 프레임워크

3. 꼭 알아야 할 5개 개념

개념한 문장 정의이 프로젝트에서 쓰이는 곳
옵션 가격 C 미래 어느 시점 T 에 S_T > K 이면 차액 지급받는 계약의 현재 가치 모든 Layer 의 공통 출력. "이 옵션은 지금 얼마짜리인가"
Implied Volatility (IV, σ) 시장 가격을 BSM 공식에 거꾸로 넣었을 때 나오는 변동성. "시장이 느끼는 불확실성 레벨" Layer B2 가 대상 변수. Layer B3 가 이것을 shift. 평가 지표의 핵심 단위
Delta (Δ) 기초자산 1원 변할 때 옵션 가격이 몇 원 변하나 (∂C/∂S). 헤지 비율. Layer A Greeks 에서 계산. Layer B4 의 baseline (BSM Δ-hedge)
Risk-neutral measure (Q) 가격 = Q 하에서의 payoff 기대값. 수학: Girsanov 로 drift μ → r 치환 Layer A MC 엔진의 drift 설정. "왜 실제 drift 안 쓰고 r 쓰냐" 의 답
CVaR@5% 하위 5% 시나리오의 평균 손실 (tail risk). "최악의 1/20 일에 평균 얼마 잃나" Layer B4 의 핵심 평가 지표. BSM Δ 대비 개선 여부 판정

6. Layer B · 4개 AI 모델의 역할과 입출력

서브레이어입력출력학습 목적추론 시 용도
B1 NN Pricer (logM, T, r, q, σ) C / K BSM/MC 의 대체 (exotic 도 가능) Risk 시스템에서 10만건 re-pricing 실시간
B2 Deep Calib Heston 5-param IV surface (5×5) 파라미터 → IV 순방향 근사 역방향 calibration: 시장 IV → params gradient descent, 1초 내
B3 News-IV 뉴스 텍스트 (event_type, confidence) 이벤트 분류 (rule/FinBERT/Claude 택1) IV_SHIFT_RULES 에 적용해 가격 선행 조정
B4 Deep Hedging [logM, T_rem, hedge, σ√T_rem, cash] hedge ∈ [0,1] 마찰 포함 CVaR 최소화 policy 매 tick 관측 → optimal hedge. BSM Δ 보다 실전에서 유리해야 함

B1 (NN Pricer) 흐름 상세

B2 (Deep Calib) 의 역방향 사용

B2 는 특이함. 순방향(Heston params → IV surface)으로 학습하고, 실제 사용은 역방향(시장 IV surface → Heston params)으로 함. 역방향은 학습 후 gradient descent 로 수행 (300 step, 1.36초). 

# 순방향 학습
python -m ai_pricing.deep_calib.train --n 3000 --epochs 40

# 역방향 사용 (시장 IV 관측 시)
from ai_pricing.deep_calib.calibrate import calibrate
p_fit, rmse = calibrate(iv_market, model, ...)
# → HestonParams(kappa=3.38, theta=0.047, xi=0.35, rho=-0.80, v0=0.04)

B3 (News-IV) 파이프라인

뉴스 텍스트                      가격 조정
   ↓                              ↑
fetch_naver_rss() / DART       call_price(replace(opt, sigma=iv_adj))
   ↓                              ↑
classify_rule/finbert/claude  adjust_iv(base, event, conf)
   ↓                              ↑
(event, confidence) ──────→ dominant_event() ────→ ΔIV lookup

B4 (Deep Hedging) RL 루프

Episode 시작: S=100, 옵션 매도, 초기 premium 받음
  ↓
step 0~29:
  obs = [logM, T_rem, current_hedge, σ√T_rem, cash_norm]
  action = policy(obs)        # hedge 수량 [0, 1]
  cash -= tc_rate * |Δhedge| * S
  S = GBM tick
  hedge_pnl = hedge * (S_next - S)
  cash = cash*exp(r*dt) + hedge_pnl
  ↓
terminal (step 30):
  payoff = max(S - K, 0)
  terminal_pnl = cash - payoff
  reward = -|terminal_pnl|    # minimize hedge error

7. Layer C / D / E — 비교 · 운영 · 가속

Layer C — Comparison Framework

experiments/compare_all.py 는 A/B1/B2/B3/B4 에서 나온 모델을 동일 옵션 패널 + 동일 GBM 경로에 투입해 5가지 수치 비교.

  • Pricing: BSM (ground truth) vs NN vs Deep Calib 프로젝션 vs News-adjusted vs Deep Hedging implied cost
  • Hedging: BSM Δ-daily vs BSM Δ-weekly vs PPO Deep Hedging
  • 산출: data/all_methods_{pricing,hedging}.csv
주의 — compare_all 의 mean_rel_err 는 deep OTM 분모 0 문제로 왜곡. 실제 평가는 scripts/bench_nn_pricer.py 의 IV-space error 를 봐야 함.

Layer D — Auto-Trading

autotrader/runner.py 가 메인 루프. 4-tier safety:

  1. --dry 플래그: KIS API 안 부르고 mock_prices() 로 시뮬. 네트워크 없이 스모크.
  2. KIS vts 환경 + KIS_DRY_RUN=true: 시세 조회 O, 주문은 mock 응답.
  3. KIS vts 환경 + KIS_DRY_RUN=false: 모의투자 계좌에 실제 주문 (가상머니).
  4. KIS prod 환경 + KIS_DRY_RUN=false + --i-understand-live: 실계좌 실주문.

추가 리스크 가드 (자동 적용):

  • 포지션 한도 20%
  • 일일 손실 −1.5% 초과 시 정지
  • 장 시작/마감 10분 매매 차단
  • API 오류 3회 연속 → 정지

Layer E — C++ MC Kernel

pybind11 + OpenMP + Xorshift64 RNG. numpy 대비 14.8× (MC 1M paths × 252 steps).

왜 필요: Layer A MC 엔진이 numpy 로 충분히 빠르지만 (antithetic + vectorized), 실무에서 10만 개 옵션 × 100만 paths 하면 numpy 도 한계. 그때 native 로 전환. 이력서 line: "Python 병목 → C++ 이식 경험" 증명. 

from fastmc import mc_euro_call, _HAS_NATIVE
assert _HAS_NATIVE, "C++ extension not built"
r = mc_euro_call(100, 100, 1, 0.03, 0, 0.2, n_paths=1_000_000, n_steps=252)
print(r.price, r.stderr)

10. 실행 절차 (A to Z)

Phase 1 · 설치 (1회)

cd d:\simeunchul\ai_pricing
python -m pip install -e packages/pricing -e packages/ai_pricing \
                      -e packages/ai_hedging -e packages/experiments \
                      -e packages/autotrader
python -m pip install torch gymnasium stable-baselines3 transformers \
                      feedparser requests pandas matplotlib
python -m pip install -e packages/fastmc  # x64 Native Tools prompt 필요

python -m pytest packages/ -q    # 37 passed

Phase 2 · 학습 (1회씩)

# NN Pricer (권장: log loss, CPU 95분)
python -m ai_pricing.nn_pricer.train --n 500000 --epochs 50 --loss log \
    --out models/nn_pricer_log_500k.pt --device cpu

# Deep Calibration (CPU 10분)
python -m ai_pricing.deep_calib.train --n 3000 --epochs 40 \
    --out models/deep_calib.pt --data data/deep_calib_cache.npz --device cpu

# Deep Hedging (CPU 20~30분, 튜닝 중)
python -m ai_hedging.agents.ppo_hedger --tc 0.003 --steps 2000000 \
    --out models/ppo_tc03.zip

Phase 3 · 평가 & 비교

# NN Pricer 개별 평가 (IV-space + strata)
python scripts/bench_nn_pricer.py --model models/nn_pricer_log_500k.pt

# 5-method 통합 비교
python -m experiments.compare_all \
    --nn-model models/nn_pricer_log_500k.pt \
    --ppo-model models/ppo_tc03.zip \
    --out data

# C++ MC 속도 벤치
python packages/fastmc/benchmarks/bench_mc.py

Phase 4 · 자동매매 (실시간)

# 완전 시뮬 (계좌 없이)
python -m autotrader.runner --symbol 069500 --dry --seconds 300 \
    --log data/runner_log.json

# 모의투자 (계좌 발급 후)
# .env 에 KIS_APP_KEY, KIS_APP_SECRET, KIS_ACCOUNT 입력
# KIS_ENV=vts 는 기본값
python -m autotrader.runner --symbol 069500 --seconds 300

Phase 5 · 실데이터 전환 (다음 단계)

  1. DART 가입 + API 키 발급 → .env 에 DART_API_KEY=...
  2. pykrx 설치 → KOSPI200 옵션 IV 일간 스냅샷 수집 스크립트 작성
  3. Layer B2 재학습 시 시장 surface 로 calibration 검증
  4. Layer B3 실제 백테스트: 뉴스 → 예측 IV shift vs 다음날 IV 변화 상관
  5. 한화 ELS 공시 PDF 다운 → Layer A 재가격 ±3% 검증
